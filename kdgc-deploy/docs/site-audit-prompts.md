## 4. 知识库严谨性（重点）

```text
审计 /knowledge/ 全部文章，按「技术严谨性」标准，而非营销文标准。

检查每篇：
1. 标题是否可检索、是否反映真实技术问题
2. 是否区分：原理说明 / 选型建议 / 工程注意 / 应用边界
3. 关键表述是否可溯源到产品公开规格
4. 有无危险误导（接线、加热、防烧损、安装方向等）
5. 分类是否清晰（原理/选型/工程/应用/维护）
6. 列表页信息密度、阅读路径、相关文章推荐是否合理
7. 英文入口若仅摘要，是否明确「全文见中文」

输出：
- 每篇文章评级：可通过 / 需修订 / 应下架重写
- 必须修改的事实性错误清单
- 建议补充的 P1 选题（若缺口明显）

注意：若线上标题仍为「知识库建设规划」，记为严重缺陷（规划页未替换为正式内容）。
```

## 11. SEO / 技术基础

```text
审计 SEO 与前端技术基础。

检查：
1. title / description / canonical 每页是否独立且准确
2. sitemap.xml 是否覆盖知识库文章与行业案例详情（不仅是列表）
3. robots.txt 是否允许抓取关键页、是否误挡内容
4. 404 页是否可用
5. 图片 alt、标题层级 H1 唯一
6. 内链：产品↔知识库↔案例
7. 性能：首屏资源体积、未压缩大图 PNG
8. HTTPS、混合内容、外链安全性
9. 结构化数据（Organization / Product）有无必要补充

输出：SEO 缺陷优先级列表。
```

## 13. 后台管理系统

```text
审计 /admin/ 完整性与可用性。

检查模块：
- 登录与 Token/权限
- 线索 Leads：列表、状态、详情
- 新闻 / 行业案例 / 知识库 / 产品 CRUD
- 统计面板

重点：
1. 后台改库后，前台静态页是否同步（CMS 与静态站双轨风险）
2. 必填校验、XSS、越权、弱口令风险
3. 发布/下架是否有状态字段且前台生效
4. 操作反馈、空状态、错误提示是否完整
5. 是否具备「从后台到前台可见」的发布流程文档

输出：后台能力成熟度（内容运营是否可独立于开发）。
```

## 14. 转化漏斗

```text

路径：
首页 → 产品对比 → 知识库选型 → 行业案例信任 → 联系表单/电话

2. 关键异议点（精度、寿命、接线、温度）是否被知识库接住

输出：漏斗断裂点 + 补位文案/入口建议。
```

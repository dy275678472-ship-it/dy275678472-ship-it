# 07 · AI 小说引擎设计

决定 LyRead 是否真正有竞争力的核心。当前 LLM 提供方：DeepSeek（`deepseek-chat`，key 走环境变量），失败回退 Pollinations 免费接口。

## 短故事生成流程

1. 输入：题材 + 想法（prompt）+ 目标字数。
2. 生成书名/简介 → 一次性大纲 → 正文（单次或分 2–3 段）。
3. 过内容审核 → 保存为 `story_projects(type=short)` + 单章 `chapters`。
4. 计费：书名 1、简介 1、正文按字数（约 10 点/2000 字）。

## 长篇小说生成流程

1. 设定：题材/风格/目标字数/人物/背景/核心冲突。
2. 生成总纲（起承转合）→ 分卷大纲 → 章纲。
3. 逐章生成，每章生成后进入「记忆更新」子流程。
4. 续写时按下述上下文策略组织 prompt。

## 上下文选取策略（关键）

生成第 N 章时，输入上下文由以下拼装（受 token 预算约束，按优先级裁剪）：

1. 作品设定（题材/风格/核心冲突）——始终包含。
2. `story_memory_snapshots` 最新快照（整书压缩记忆）。
3. 相关 `characters` + 最近 `character_states`（出场人物优先）。
4. 未回收 `foreshadowings`（status=open）。
5. 最近 K 章的 `chapter_summaries`（默认 K=5）。
6. 最近 1–2 章正文（保证文风与衔接）。
7. 本章章纲（目标剧情、爽点标签）。

token 超预算时的裁剪顺序：正文 > 远期摘要 > 次要人物状态；设定/未回收伏笔/当前章纲不裁剪。

## 记忆更新子流程（每章成功后）

1. 生成本章摘要 → 写 `chapter_summaries`。
2. 抽取人物变化 → 更新/新增 `character_states(after_chapter=N)`。
3. 检测新登场设定 → 写 `world_settings`。
4. 识别新埋伏笔（写入 open）与本章回收的伏笔（置 recovered）。
5. 每 M 章（默认 10）重算一次 `story_memory_snapshots`。
6. 冲突检测：人物姓名/关系/关键设定与历史记录矛盾时，产出一致性报告（不阻断，提示用户）。

## 失败与重试

- 模型超时/报错：`generation_jobs` 记 error_code，`retry_count` 自增，最多 2 次；仍失败 → 全额返还点数、job=failed。
- 多模型切换：DeepSeek 失败按配置回退备用（Pollinations/其他 OpenAI 兼容端点）。
- 成本核算：记录 input/output tokens，用于每章真实成本分析（防止固定价亏损）。

## 质量评分（P1，先只做「生成前预测」）

- 生成前：标题吸引力、开篇钩子、冲突强度、人物辨识度、情绪张力、节奏、题材适配度。
- 发布后（有真实流量再做）：点击率、首屏停留、首章完读、下一章阅读、收藏、分享、试读转创作。
- 无真实数据时只显示「内容质量预测」，不得声称「爆款命中率」。

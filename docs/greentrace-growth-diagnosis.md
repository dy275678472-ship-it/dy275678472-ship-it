# greentrace.com.cn 商业增长诊断报告

> 诊断时间：2026-07-19 · 数据源：线上探测 + 首尔服务器 `/opt/greentrace` 代码与 SQLite 审计  
> 综合评分：**52 / 100**

---

## 执行摘要

绿迹具备**强内容资产骨架**（77 城、235+ 路线、16 篇博客、AI 友好 llms.txt）和清晰的视觉品牌（深绿 + 奶油色），但存在**致命转化断裂**（城市/路线页「立即预约」指向自身 `#cta`、无预约表单）、**SEO 基建硬伤**（sitemap 全用 `www.` 而 canonical 用 apex、博客未进 sitemap、IndexNow 密钥错误）、以及**双重定位冲突**（可持续 Citywalk 内容站 vs 本地向导撮合平台 vs 外部 `greenyoo.cn` 地陪品牌）。当前最适合的主定位是：**「低碳城市深度探索内容站 + 轻量向导预约入口」**——先把搜索流量与内容留存做实，再激活向导供给变现。

## 1. 网站整体定位分析

### 行业与赛道
- **行业**：旅行 / 本地生活服务
- **细分**：可持续城市旅行内容（Citywalk / 骑行 / 公交）+ 本地向导（地陪）撮合
- **窗口**：小红书已教育「地陪」市场；携程当地向导偏标准化；中间「深度体验 + 中价位」空白（站内合伙人方案已论证）

### 核心产品 / 服务

| 模块 | 现状 | 成熟度 |
|------|------|--------|
| 首页品牌叙事 | 「用脚步丈量城市」+ 76+ 城 / 235+ 路线 | ✅ 清晰 |

### 目标用户画像
1. **深度自由行用户**（22–35 岁）：搜「成都 Citywalk」「杭州骑行路线」，要本地感而非景点打卡
2. **低碳 / 慢旅行兴趣用户**：公交探索、菜市场、旧物市集
3. **入境 / 跨城差旅短游**：半日轻探、找本地向导
4. **供给侧**：本地向导、城市主理人、地陪（小红书活跃）

### 首访认知清晰度
- **清晰**：首屏 H1「用脚步丈量城市」+ Citywalk / 骑行 / 公交，可持续旅行主张明确
- **模糊**：同一站同时推「内容攻略」与「预约向导」；城市页 CTA「立即预约」无表单，用户无法完成下一步
- **冲突**：`llms.txt` 自称「本地向导平台」、首页自称「可持续城市旅行指南」、小红书文案推 `greenyoo.cn`——三套叙事并存

## 4. UX 与转化优化

### 用户路径与流失点

```
首页 → 城市/频道 → 路线/攻略 → 信任 → 预约/咨询
         ↓              ↓           ↓
      认知清晰       内容可读    ❌ CTA 自指无表单
                                 真实注册用户仅 7
                                 tour_requests 仅 4
```

### 关键流失节点
1. **城市页 / 路线页「立即预约」→ `#cta`**：按钮点自己，**无姓名/微信/日期表单**（`server.py` 模板硬编码自指链接）
2. **无邮件订阅**：博客与首页零邮箱捕获
3. **Klook 仅页脚**：出行预订曝光弱，CPS 难起量
4. **注册/登录入口对 C 端弱**：供需两侧都未形成账号体系习惯
5. **评价可信度**：3067 条评价 + 1172 订单 vs 7 用户 → 访客若识破将严重损信任

### 转化提升方案（可执行）

| 动作 | 说明 | 预期 | 成本 |
|------|------|------|------|
| P0 嵌入预约表单 | 字段：姓名、微信、城市、日期、人数、预算；POST 已有 `/api` tour_requests | 咨询量从近 0 → 可测 | 低（改模板） |
| 城市页中部双 CTA | 「收藏这条路线」+「预约向导」 | 降低单 CTA 压力 | 低 |
| 博客文末订阅 | 复用邮箱收集 → Newsletter | 留存池 | 低 |
| Klook 组件上移 | 城市页「住哪里」模块（参考 cosgo HotelSearchWidget） | CPS | 低 |
| 信任条 | 展示可验证数据：开放城市数、路线数；慎用「3067 评价」直至清洗 | 降低跳出 | 低 |
| 主理人 / 向导分流 | 页脚与城市页底部分开入口 | 供给增长 | 低 |

## 5. UI 视觉设计分析

### 评分：7.0 / 10
- **优点**：绿色系 token 完整（`--green-dark` → `--cream`）、毛玻璃导航、圆角卡片、与「可持续」气质匹配；优于多数中小旅行站
- **不足**：系统字体栈偏默认；首页信息块偏多；城市页 CTA 区视觉有按钮但无表单，产生「假完成」感；部分 emoji 标题偏运营号风格

### 设计检查
| 项 | 评价 |
|----|------|
| 第一印象 | 清新、环保、可信起点 |
| 专业度 | 中上；缺产品级动效与摄影一致性 |
| 品牌感 | 「绿迹」叶形 logo 有记忆点 |
| 科技感 | 中等；AI API 对外强、对内 UI 未体现 |
| 布局 | 首屏品牌尚可；下方城市网格标准 |
| 色彩 | 深绿体系清晰，避免再引入紫色流行风 |

### UI 升级方向
1. **首页**：首屏只保留品牌 + 一句支持句 + 双 CTA（探索城市 / Citywalk）；统计可保留一行
2. **城市页**：预约区改为真实表单卡片（非空按钮）
3. **字体**：引入一套中文显示字体（如站酷快乐体以外的人文sans），避免纯系统栈
4. **组件**：路线卡统一封面比例、难度标签、预计时长
5. **参考**：Notion 清晰度 + AllTrails 路线信息密度 + 少部分 Stripe 信任留白
